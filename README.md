# Raith Automatic Beam Calibration

An automatic calibration script with a visual progress dashboard, made for use on Raith's VOYAGER EBL (Electron Beam Lithography) Tool, using the Raith IronPython scripting host. It drives to saved Nanorods, Chessy, Faraday-cup and sample positions; runs focus, stigmation and position alignment; measures beam current; and saves the active beam mode.

**Current status: partial integration.** The default sequence stops at the sample's three-hole exposure step because that operation is not implemented. The stage-Z adjustment loop is also not implemented. This is not an end-to-end validated instrument release.

## Planned sequence

| Location | Steps in execution order |
| --- | --- |
| Nanorods | Move; beam focus; stigmator; beam refocus; operator confirms focus once; field focus; field stigmator; field refocus. |
| Chessy | Move; beam focus; stigmator; beam refocus; position coarse; position fine; position final. |
| Faraday Cup | Move; measure current at the named cup; save the active beam mode. |
| Sample | Move; **expose three holes (missing)**; beam focus; **adjust Z to working distance (missing)**; position final. |

All 23 steps are represented in the dashboard. Every stigmator is immediately followed by the corresponding focus procedure. Position alignment checks the reported `DistortionFomInNM` against strict limits of `<100`, `<50` and `<10` nm for coarse, fine and final, with at most three attempts. Focus uses the `ParabolicAutoFocus` option and one initial operator confirmation; no focus FOM threshold is applied.

The intended sample working distance is **20.000 +/- 0.005 mm**. This value is configuration for the unfinished Z adapter, not an active control loop.

## Runtime requirements

The main script imports .NET and `Raith.CommonLib` and expects existing host objects `TM`, `ST`, `UI` and `AD`. `CC` supports column identity checking and the standalone WD getter; `IP` supports the optional image pane; `PG` supports conditional emulated-image setup. The script does not create or initialize those clients. Exact supported Raith software, assembly and IronPython versions have not been recorded.

Running the main script with ordinary desktop Python is not the instrument launch procedure. No pip package or standalone instrument connection is supplied.

## Important operating behavior

- Loading in the host opens the dashboard. Movement, alignment, measurement and saving begin only after **Start sequence**.
- The saved-position indexes are Nanorods **3**, Faraday Cup **2**, Chessy **4**, sample **5**. This allows easy updates to the positions using the Raith GUI's Stage Controller positionlist. These indexes can be changed to match your own positions.
- Images reuse data generated by the alignment routines; the dashboard requests no extra scans. Image receipt does not establish acceptable focus or alignment.
- Save writes the existing active beam mode through `TM.SaveSettings()`. Identity checks guard against saving a different mode.
- **Stop sequence** stops advancement and attempts to stop automatic alignment. Stage motion or current measurement may continue; use the instrument's native stop control when necessary.
- A new Start begins the whole sequence again. There is no resume-from-step, CJob-style job editor or exposure queue yet. Working on this and will be added soon.

## Verification

Run from the repository directory with desktop Python:

```text
python -m unittest discover -s tests -v
```

All **77 offline tests passed** on Python 3.13 during preparation of this snapshot. Tests exercise sequence/event handling, result gates, saving, diagnostics and dashboard state/layout. They do not validate proprietary GUI rendering, hardware motion, meter accuracy, autofocus quality, persistence, or a complete live sequence.

When run on the EBL tool sandbox, it successfully shows a working image display, beam calibration, a successful faraday cup measurement and a beam-mode Save. The evidence and remaining limitations are recorded separately in [API status](docs/API_STATUS.md).
